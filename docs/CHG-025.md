# CHG-025 — Controlled ICMP rate anomaly detection

## Status

**Pre-UAT / detection-only.**

This branch defines the governed signature and the UAT contract. It does not claim successful runtime detection until the VM validation described below is completed.

## Objective

Add one independent, bounded Suricata detection for an ICMP rate anomaly inside the isolated Mini-SOC lab and validate it through the existing telemetry pipeline:

`SOC-TEST-01 -> SOC-GW-01/Suricata -> EVE JSON -> Wazuh Agent -> Wazuh Manager/Dashboard -> SOC L1 triage`.

The goal is detection engineering and safe portfolio evidence, not denial-of-service execution.

## Problem and risk

The existing SID `1000001` is a deterministic authorized ICMP test signal used by CHG-019 and CHG-021. Reusing or relabeling it as a DoS detection would weaken evidence integrity and could couple unrelated Active Response behavior to a new use case.

CHG-025 therefore uses a new local SID and remains detection-only until positive/negative validation is complete.

## Minimum change

The GitHub-governed local signature file is:

`config/gateway/suricata/mini-soc-local.rules`

It contains the already validated CHG-019 rule unchanged plus the new CHG-025 rule:

```
alert icmp 10.77.0.10 any -> 10.77.0.1 any (msg:"MINI-SOC Controlled ICMP Rate Anomaly"; itype:8; threshold:type both, track by_src, count 20, seconds 1; sid:1000002; rev:1;)
```

Design constraints:

- exact source: `SOC-TEST-01` / `10.77.0.10`;
- exact destination: `SOC-GW-01` / `10.77.0.1`;
- protocol: ICMP Echo Request only;
- threshold: 20 matches in one second, tracked by source;
- local SID: `1000002`;
- passive alert only;
- no `drop`, `reject`, IPS/NFQUEUE or Active Response;
- existing SID `1000001` and Wazuh rule `100021` remain unchanged.

The threshold is intentionally conservative for a lab demonstration. It is a controlled rate-anomaly signal, not a claim of production-grade DoS detection.

## Source of truth

GitHub is the governed source for the local signatures. After CI succeeds, UAT deploys this exact file to:

`/var/lib/suricata/rules/mini-soc-local.rules`

on `SOC-GW-01`.

This avoids maintaining an undocumented second copy of the local rules.

## Static validation

CI must:

- parse the local signatures with Suricata test mode;
- retain both SIDs `1000001` and `1000002`;
- confirm the CHG-025 threshold contract;
- reject accidental `drop` or `reject` actions in the local rule file.

Runtime activation remains gated on a second `suricata -T` validation on `SOC-GW-01`.

## Planned UAT

### Negative / baseline test

From `SOC-TEST-01`:

```bash
ping -c 5 -i 1 10.77.0.1
```

Expected result:

- connectivity succeeds;
- SID `1000001` may behave according to its existing deterministic test semantics;
- SID `1000002` must not alert because the rate condition is not met.

### Positive bounded test

From `SOC-TEST-01`:

```bash
sudo hping3 --icmp -c 30 -i u20000 10.77.0.1
```

This sends 30 ICMP packets with a 20 ms interval (approximately 50 packets/second for well under one second). It is intentionally bounded and must only target the isolated gateway.

Expected result:

- Suricata emits SID `1000002`;
- EVE JSON records the alert;
- Wazuh receives the event through the existing agent path;
- Wazuh native Suricata processing exposes the event in the Dashboard;
- no automatic containment occurs;
- gateway forwarding/firewall policy is unchanged.

The `--flood` option is explicitly out of scope.

## SOC L1 disposition

Expected analyst disposition for the authorized UAT:

**True Positive — Authorized Security Test / Benign**

- escalation: no, unless observed behavior deviates from the test plan;
- containment: no;
- Active Response: no;
- MITRE ATT&CK mapping: not assigned solely for portfolio appearance.

## Regression checks

After UAT:

- `suricata` active;
- `wazuh-agent` active;
- `nftables` active;
- forwarding policy unchanged;
- existing CHG-019 detection still available;
- existing CHG-021 Active Response contract remains scoped to Wazuh rule `100021` / SID `1000001`.

## Rollback

1. Restore the pre-CHG-025 local rule file on `SOC-GW-01`.
2. Run `suricata -T -c /etc/suricata/suricata.yaml` and require exit code 0.
3. Reload/restart Suricata only after successful validation.
4. Confirm Suricata, Wazuh Agent and nftables health.
5. Confirm existing SID `1000001` behavior remains intact.

No database, route, persistent nftables, Wazuh manager rule or Active Response rollback is required.

## Evidence handling

Do not commit raw PCAP, EVE logs, credentials, API keys, private host telemetry or unrelated LAN information.

Retain only sanitized evidence needed to demonstrate:

- rule design;
- CI validation;
- bounded positive/negative UAT;
- Wazuh visibility;
- analyst disposition;
- regression and rollback readiness.

## Residual risk

A lab-tuned threshold is not a production DoS control and may not generalize to different workloads or traffic baselines. CHG-025 intentionally demonstrates controlled detection engineering rather than production capacity planning or availability protection.

## Portfolio claim

After successful UAT, the defensible claim is:

> Designed and validated a scoped Suricata rate-based network detection, tested positive and negative cases with bounded authorized traffic, centralized the alert in Wazuh, and preserved separation between detection and response through governed change control.
