# CHG-025 — Controlled UDP rate anomaly detection

## Status

**Pre-UAT / detection-only.**

This branch defines the governed signature and UAT contract. It does not claim successful runtime detection until VM validation is completed.

## Objective

Add one independent, bounded Suricata detection for a short UDP rate anomaly inside the isolated Mini-SOC lab and validate it through the existing telemetry pipeline:

`SOC-TEST-01 -> SOC-GW-01/Suricata -> EVE JSON -> Wazuh Agent -> Wazuh Manager/Dashboard -> SOC L1 triage`.

The goal is detection engineering and safe portfolio evidence, not denial-of-service execution.

## Risk discovered before UAT

The first draft reused ICMP Echo Request traffic. That was rejected before traffic generation because the existing CHG-019 SID `1000001` matches the same flow and CHG-021 intentionally maps that SID to Wazuh rule `100021` and Active Response.

Running the ICMP draft would therefore have violated CHG-025's detection-only objective by triggering the existing containment path.

The design was corrected before positive or negative UAT.

## Minimum change

Canonical rule source:

`config/gateway/suricata/mini-soc-local.rules`

New CHG-025 rule:

```
alert udp 10.77.0.10 any -> 10.77.0.1 65000 (msg:"MINI-SOC Controlled UDP Rate Anomaly"; threshold:type threshold, track by_src, count 20, seconds 1; sid:1000002; rev:1;)
```

Design constraints:

- exact source: `SOC-TEST-01` / `10.77.0.10`;
- exact destination: `SOC-GW-01` / `10.77.0.1`;
- protocol: UDP;
- destination port: `65000`, verified unused before UAT;
- threshold: alert on the 20th match inside one second, tracked by source;
- local SID: `1000002`;
- passive alert only;
- no `drop`, `reject`, IPS/NFQUEUE or Active Response;
- existing SID `1000001` and Wazuh rule `100021` remain unchanged.

The threshold is deliberately lab-scoped. It is a controlled rate-anomaly signal, not a production-grade DoS control.

## Source of truth

GitHub is the governed source for local signatures. UAT deploys the exact CI-validated file to:

`/var/lib/suricata/rules/mini-soc-local.rules`

on `SOC-GW-01`.

## Static validation

CI must:

- parse the local signatures with Suricata test mode;
- retain SIDs `1000001` and `1000002`;
- confirm UDP destination port `65000`;
- confirm the 20-in-1-second threshold contract;
- reject accidental `drop` or `reject` actions.

Runtime activation remains gated on `suricata -T` on `SOC-GW-01`.

## Planned UAT

### Pre-test collision check

On `SOC-GW-01`, confirm no UDP service is listening on port `65000`.

### Negative / baseline test

From `SOC-TEST-01`:

```bash
sudo hping3 --udp -p 65000 -c 5 -i u1000000 10.77.0.1
```

Expected result:

- five bounded UDP packets are sent at approximately one packet/second;
- SID `1000002` does not alert;
- SID `1000001` is not matched because the traffic is UDP, not ICMP;
- CHG-021 Active Response is not triggered.

### Positive bounded test

From `SOC-TEST-01`:

```bash
sudo hping3 --udp -p 65000 -c 30 -i u20000 10.77.0.1
```

This sends 30 UDP packets with a 20 ms interval, approximately 50 packets/second for well under one second.

Expected result:

- Suricata emits SID `1000002`;
- EVE JSON records the alert;
- Wazuh receives the event through the existing agent path;
- the event is visible in the Dashboard;
- SID `1000001` / Wazuh rule `100021` is not triggered by the test;
- no automatic containment occurs;
- gateway forwarding/firewall policy remains unchanged.

The `--flood` option is explicitly out of scope.

## SOC L1 disposition

Expected disposition:

**True Positive — Authorized Security Test / Benign**

- escalation: no unless behavior deviates from the plan;
- containment: no;
- Active Response: no;
- MITRE ATT&CK mapping: not assigned solely for portfolio appearance.

## Regression checks

After UAT:

- `suricata`, `wazuh-agent` and `nftables` active;
- forwarding policy unchanged;
- CHG-019 SID `1000001` remains available;
- CHG-021 remains scoped to Wazuh rule `100021` / SID `1000001`;
- no runtime containment state is created by CHG-025.

## Rollback

1. Restore the pre-CHG-025 local rule file on `SOC-GW-01`.
2. Run `suricata -T -c /etc/suricata/suricata.yaml` and require exit code 0.
3. Reload/restart Suricata only after successful validation.
4. Confirm Suricata, Wazuh Agent and nftables health.
5. Confirm existing SID `1000001` behavior remains intact.

No database, route, persistent nftables, Wazuh manager rule or Active Response rollback is required.

## Evidence handling

Do not commit raw PCAP, EVE logs, credentials, API keys, private host telemetry or unrelated LAN information.

Retain sanitized evidence of rule design, CI validation, bounded positive/negative UAT, Wazuh visibility, analyst disposition, regression checks, and the pre-UAT design correction.

## Residual risk

A lab-tuned threshold does not generalize to production traffic. UDP to a deliberately unused lab port is a deterministic test harness, not evidence of real-world malicious intent or service impact.

## Portfolio claim

After successful UAT, the defensible claim is:

> Designed and validated a scoped Suricata rate-based network detection, identified and removed a collision with an existing automated-response path before testing, validated positive and negative cases with bounded authorized traffic, and centralized the alert in Wazuh under governed change control.
