# CHG-025 — Controlled UDP rate anomaly detection

## Status

**UAT validated / detection-only.**

The governed signature, runtime activation and end-to-end UAT were completed on 2026-10-07. CHG-025 remains intentionally passive: it detects and centralizes the event but does not authorize containment.

## Objective

Add one independent, bounded Suricata detection for a short UDP rate anomaly inside the isolated Mini-SOC lab and validate it through the existing telemetry pipeline:

`SOC-TEST-01 -> SOC-GW-01/Suricata -> EVE JSON -> Wazuh Agent -> Wazuh Manager/Indexer/Dashboard -> SOC L1 triage`.

The goal is detection engineering and safe portfolio evidence, not denial-of-service execution.

## Security design correction before traffic UAT

The first draft reused ICMP Echo Request traffic. Before any positive or negative traffic test, review of CHG-021 showed that the same traffic would also match existing SID `1000001`, which is intentionally mapped to Wazuh rule `100021` and Active Response.

That would have violated CHG-025's detection-only objective and conflated two independent controls.

The design was therefore changed to a dedicated UDP flow on an unused gateway port. Existing SID `1000001`, Wazuh rule `100021` and CHG-021 Active Response were left unchanged.

## Implemented rule

Canonical source:

`config/gateway/suricata/mini-soc-local.rules`

CHG-025 signature:

```
alert udp 10.77.0.10 any -> 10.77.0.1 65000 (msg:"MINI-SOC Controlled UDP Rate Anomaly"; threshold:type threshold, track by_src, count 20, seconds 1; sid:1000002; rev:1;)
```

Design constraints:

- exact source: `SOC-TEST-01` / `10.77.0.10`;
- exact destination: `SOC-GW-01` / `10.77.0.1`;
- protocol: UDP;
- destination port: `65000`, verified unused before UAT;
- threshold: alert on the 20th match inside one second, tracked by source;
- local SID: `1000002`;
- action: `alert` only;
- no `drop`, `reject`, IPS/NFQUEUE or Active Response;
- existing SID `1000001` and Wazuh rule `100021` unchanged.

This is a deterministic lab threshold, not a production-grade denial-of-service control.

## UAT

### Pre-test scope check

`UDP/65000` was confirmed unused on `SOC-GW-01` before traffic generation.

The traffic generator was installed only on the disposable `SOC-TEST-01` workload. No load-generation tooling was added to the gateway or manager.

### Negative / baseline test

Validated command from `SOC-TEST-01`:

```bash
hping3 --udp -p 65000 -c 5 -i 1 10.77.0.1
```

Observed:

- 5 packets transmitted at low rate;
- no SID `1000002` event in EVE JSON;
- no new SID `1000001` event;
- no new CHG-021 Active Response entry;
- runtime nftables blocking set remained empty.

Result: **PASS**.

### Positive bounded test

Validated command from `SOC-TEST-01`:

```bash
hping3 --udp -p 65000 -c 30 -i u20000 10.77.0.1
```

The generator transmitted exactly 30 packets with a 20 ms interval. The `--flood` option was not used and remains out of scope.

Suricata produced:

- timestamp: `2026-10-07T02:55:53-03:00`;
- source: `10.77.0.10`;
- destination: `10.77.0.1:65000/UDP`;
- SID: `1000002`;
- signature: `MINI-SOC Controlled UDP Rate Anomaly`;
- action: `allowed`.

No new SID `1000001` event was generated and no CHG-021 Active Response `ADD` occurred.

Result: **PASS**.

## Operational observation

During an earlier activation checkpoint, before the final UDP UAT, a Suricata service restart exceeded the systemd shutdown timeout because flow recycler threads did not terminate in time. systemd issued SIGKILL to the old process and the new Suricata instance started successfully.

The signature configuration had already passed `suricata -T`; the final UDP rule was activated with Suricata's hot rule reload instead of performing another service restart. The reload completed successfully and avoided additional service interruption.

This is retained as an availability/operability observation rather than misclassified as a detection failure.

## Rollback

1. Restore `/var/lib/suricata/rules/mini-soc-local.rules.pre-chg025`.
2. Run `suricata -T -c /etc/suricata/suricata.yaml` and require exit code 0.
3. Prefer a validated rule reload for a signature-only rollback; restart only if required.
4. Confirm Suricata, Wazuh Agent and nftables health.
5. Confirm SID `1000001` remains functional and no CHG-025 rule remains loaded.

No database, route, persistent nftables, Wazuh manager rule or Active Response rollback is required.

## Residual risk

- The threshold is lab-specific and is not suitable for production without traffic baselining and alert-volume analysis.
- UDP/65000 is deliberately an unused lab destination, so the test demonstrates detection logic rather than application availability impact.
- A single deterministic source/destination pair does not model distributed volumetric traffic.
- The Suricata shutdown timeout observed during restart should be investigated separately if clean restart behavior becomes an operational requirement.
