# CHG-016 — SOC-TEST-01 minimum operability baseline

## Scope

Complete a reproducible operational baseline for the disposable workload behind SOC-GW-01 without adding a bypass network path.

## Implemented state

- Debian 13 boots from its virtual disk with installation media detached.
- The VM retains a single VirtualBox Internal Network adapter on `SOC-LAB-INTERNAL`; no NAT or bridged adapter was added.
- `ifupdown` remains the network configuration authority.
- Static IPv4 remains `10.77.0.10/24` with default route through `10.77.0.1`.
- DNS is declared with `dns-nameservers` in the existing interface configuration and materialized by `resolvconf`.
- Debian network repositories replaced the obsolete installation-media APT source.
- OpenSSH Server is installed, active and enabled.

## Validation

Before the DNS change, the workload reached both SOC-GW-01 and an Internet IP but could not resolve `deb.debian.org`. This isolated the fault to name resolution rather than routing or NAT.

After configuration and reboot, `/etc/resolv.conf` was generated by `resolvconf` with the configured resolvers and `deb.debian.org` resolved successfully.

SSH management was validated through the existing security boundary:

```text
operator host -> loopback-only SSH forward -> SOC-GW-01 -> SSH -> SOC-TEST-01
```

No direct NAT port-forward, bridged adapter, or second upstream path was added to SOC-TEST-01.

Post-reboot validation confirmed:

- `10.77.0.10/24` remained assigned to the internal interface.
- The default route remained through `10.77.0.1`.
- SSH remained active and enabled.
- The gateway and an Internet IP were reachable with zero packet loss in the controlled checks.
- DNS resolution remained functional.

A powered-off snapshot named `BASELINE-TEST-READY` was created after successful UAT.

## Rollback

- Restore the pre-change APT source backup if repository configuration must be reverted.
- Remove OpenSSH Server if remote management is no longer required.
- Revert DNS configuration through the existing `ifupdown` source of truth.
- Restore `BASELINE-TEST-READY` for future controlled test resets.

## Security rationale

The change improves operability without weakening segmentation. SOC-TEST-01 still has one isolated interface and must traverse SOC-GW-01 for routed traffic. DNS and SSH were added only after the routed boundary had been validated. Existing Wazuh endpoint/manager networking was not modified.

## Out of scope

Suricata, gateway Wazuh Agent enrollment, Active Response, YARA/VirusTotal, gateway INPUT/OUTPUT hardening, and changes to the existing Wazuh endpoint/manager path.
