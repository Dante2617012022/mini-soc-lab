# CHG-021 — Controlled Wazuh Active Response with safe rollback

## Objective

Demonstrate a bounded detection-to-response workflow in the Mini-SOC lab while preserving least privilege, deterministic rollback, analyst governance, and the existing nftables firewall architecture.

This change intentionally avoids broad automatic blocking, permanent bans, account actions, and introducing iptables as a second firewall technology.

## Scope and architecture

The response is driven by the existing controlled Suricata signature (SID `1000001`) and the scoped Wazuh child rule `100021`.

Flow:

`SOC-TEST-01 (10.77.0.10) → Suricata on SOC-GW-01 → Wazuh rule 86601 → local rule 100021 → Wazuh Active Response on SOC-GW-01 → runtime nftables containment → timeout rollback`

The response executes only on the agent that generated the alert (`location=local`). The persistent gateway ruleset in `/etc/nftables.conf` is not modified.

## Security decisions

- Detection and response remain separate controls.
- Generic Wazuh rule `86601` was rejected as the direct trigger because it also receives unrelated Suricata alerts.
- Local rule `100021` matches only `alert.signature_id=1000001`; positive and negative `wazuh-logtest` cases were validated before enabling response.
- Built-in `firewall-drop` was not used because the gateway is nftables-only; installing iptables only for the demonstration would create a second firewall technology/source of truth.
- The custom response accepts the event source field but enforces an exact safety allowlist of `10.77.0.10`.
- The script uses the absolute nftables path `/usr/sbin/nft`.
- Containment is implemented in the dedicated runtime table `inet mini_soc_ar`, with a forward hook at priority `-10`.
- Only forwarded traffic sourced from the controlled test workload is dropped. Gateway management and Wazuh telemetry are outside this rule's blast radius.
- Wazuh timeout is 60 seconds and the response implements stateful `add/delete` behavior.
- No secrets, PCAPs, raw telemetry, credentials, or production data are committed.

## Configuration

Manager command definition:

```xml
<command>
  <name>mini-soc-nft-block</name>
  <executable>mini-soc-nft-block.py</executable>
  <timeout_allowed>yes</timeout_allowed>
</command>
```

Scoped response:

```xml
<active-response>
  <disabled>no</disabled>
  <command>mini-soc-nft-block</command>
  <location>local</location>
  <rules_id>100021</rules_id>
  <timeout>60</timeout>
</active-response>
```

The runtime script is versioned at `scripts/active-response/mini-soc-nft-block.py`. The manual protocol harness is retained at `scripts/active-response/chg-021-harness.py` as reproducible UAT tooling.

2. `blocked_ipv4` contained only `10.77.0.10`.

### End-to-end automatic UAT

Baseline internet connectivity from SOC-TEST-01 succeeded.

One authorized ICMP event to `10.77.0.1` triggered the existing Suricata SID `1000001`. Approximately five seconds later, forwarded connectivity from SOC-TEST-01 was blocked (3 transmitted / 0 received / 100% loss).

SOC-GW-01 Active Response evidence:

```text
2026/10/05 04:19:40 mini-soc-nft-block.py: ADD source=10.77.0.10
2026/10/05 04:20:41 mini-soc-nft-block.py: DELETE source=10.77.0.10
```

The delete occurred automatically after the configured timeout. The nftables set was empty afterward.

Post-response recovery from SOC-TEST-01: 3 transmitted / 3 received / 0% loss.

Final SOC-GW-01 health:

- `wazuh-agent`: active
- `suricata`: active
- `nftables`: active
- `net.ipv4.ip_forward=1`

Disposition: **True Positive — Authorized Security Test / Benign**. Automated containment was intentionally executed as part of the authorized test. No adversary ATT&CK technique is assigned to the benign deterministic trigger.

## Rollback

1. Disable/remove the CHG-021 `active-response` and custom `command` blocks on the manager.
2. Restore the pre-change manager configuration from `/var/ossec/etc/ossec.conf.pre-chg021-ar` when performing full rollback.
3. Validate with `/var/ossec/bin/wazuh-analysisd -t` before restarting the manager.
4. Remove `/var/ossec/active-response/bin/mini-soc-nft-block.py` from SOC-GW-01.
5. Delete the runtime table if present: `/usr/sbin/nft delete table inet mini_soc_ar`.
6. Restart/revalidate Wazuh components and verify agent connectivity.

The persistent `/etc/nftables.conf` does not require restoration because CHG-021 never modifies it.

## Residual risks and limitations

- The response is deliberately lab-scoped to `10.77.0.10`; it is not a production generalized containment engine.
- A reload/restart of the persistent nftables service flushes runtime-only CHG-021 state. For this temporary lab containment that behavior is fail-open and accepted; production response would require explicit ownership and persistence design.
- The runtime table remains present with an empty set after timeout. It has no blocking effect.
- Active Response reduces time-to-containment but does not replace analyst triage. Automatic actions must remain proportional to detection confidence and blast radius.

## Portfolio evidence

CHG-021 demonstrates detection engineering, scoped automation, least privilege, defense in depth, bounded blast radius, rollback, negative testing, end-to-end UAT, operational health validation, and change governance without introducing controls that conflict with the existing firewall architecture.
