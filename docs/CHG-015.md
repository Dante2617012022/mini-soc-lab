# CHG-015 — Controlled gateway forwarding

## Scope

Validate controlled forwarding from the isolated test segment through SOC-GW-01 without changing the existing Wazuh endpoint/manager path.

## Validated state

- SOC-GW-01 internal interface: 10.77.0.1/24.
- SOC-TEST-01: 10.77.0.10/24 with 10.77.0.1 as gateway.
- nftables FORWARD policy is default deny.
- Established and related return traffic is allowed.
- New forwarding is limited to traffic from 10.77.0.0/24 on the internal interface toward the VirtualBox NAT upstream.
- Masquerade is limited to the same lab subnet and upstream interface.
- IPv4 forwarding is enabled persistently only after the firewall policy was validated.
- No route to the physical LAN was introduced.

## Validation

Before forwarding was enabled, SOC-TEST-01 reached SOC-GW-01 but could not reach an Internet IP.

The nftables configuration passed a syntax check before activation. The firewall was loaded before IPv4 forwarding was enabled.

After activation, SOC-TEST-01 reached the Internet through SOC-GW-01. A controlled gateway reboot then confirmed persistence of the internal address, default route, nftables policy and IPv4 forwarding. Final UAT from SOC-TEST-01 reached both the gateway and an Internet IP with 4/4 ICMP replies and 0% loss.

## Rollback

Disable IPv4 forwarding, remove the dedicated persistent forwarding setting, restore the pre-change nftables configuration, or restore the BASELINE-GW-READY snapshot if required. SOC-TEST-01 remains disposable.

## Out of scope

DNS and SSH on SOC-TEST-01, gateway INPUT/OUTPUT hardening, Suricata, Wazuh Agent enrollment on the gateway, and Active Response.

No credentials, secrets, raw packet captures, or unnecessary physical-LAN details are stored in this evidence.
