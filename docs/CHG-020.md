# CHG-020 — Local YARA detection and VirusTotal hash-only enrichment

## Objective

Validate a minimal file-triage workflow on `SOC-ENDPOINT-01` using local YARA detection and optional VirusTotal hash-only enrichment. The change deliberately avoids file upload, automated containment and Active Response.

## Scope and trust boundary

- Target: `SOC-ENDPOINT-01`, Debian 13 (trixie).
- Existing Wazuh agent remained active and unchanged.
- YARA is the local detection control.
- VirusTotal is an external, optional enrichment service and is not a source of truth for local detection.
- Only a SHA-256 hash crosses the third-party trust boundary.
- No sample, private/production file or API key is stored in the repository.

## Implementation

The Debian package authority exposed `yara 4.5.2-1` from `trixie/main`. Only `yara` and its required `libyara10` dependency were installed.

A dedicated harness was created outside the repository:

- rule: `/opt/mini-soc/yara/rules/mini-soc-test.yar`
- benign artifact: `/opt/mini-soc/yara/test/authorized-test.txt`
- ownership: `root:root`
- permissions: `0644`

The isolated rule matches the deterministic marker:

`MINI-SOC-YARA-AUTHORIZED-TEST-2026`

No malware or malware sample was used.

## Validation evidence

Local YARA produced the expected match:

`MINI_SOC_Authorized_Test /opt/mini-soc/yara/test/authorized-test.txt`

The artifact SHA-256 was computed locally:

`8fd07710f8d2a2a162de785b2a9447b6dc0035c74be05cca523cf29bc27f8197`

VirusTotal was queried using only that SHA-256. The service returned:

- HTTP status: `404`
- result: `NotFoundError`

Interpretation: VirusTotal had no existing report for the hash. This is **unknown/not indexed**, not evidence that the artifact is clean or benign.

The API key was entered interactively into an environment variable, was not written to a repository file, and was removed from the shell environment after the lookup.

After removing the API key, the same local YARA command still produced the expected match. This validates graceful degradation: loss or unavailability of the external enrichment service does not disable local detection.

## SOC L1 disposition

**True Positive — Authorized Security Test / Benign**

The YARA signature correctly matched the controlled artifact. The activity was expected and authorized. No escalation or containment is required.

No MITRE ATT&CK technique is assigned. The event is a deterministic validation artifact and forcing an adversary technique would misrepresent the evidence.

## Security decisions

- Local detection precedes external enrichment.
- Data minimization: only SHA-256 is disclosed to VirusTotal.
- No file upload to third parties.
- API credentials remain outside version control and evidence.
- A VirusTotal miss is not interpreted as a clean verdict.
- Third-party failure is fail-independent from local YARA detection.
- No deletion, quarantine, blocking or Active Response was introduced.
- Wazuh configuration was not modified because central YARA ingestion is not required to prove this control and would unnecessarily expand CHG-020.

## Rollback

On `SOC-ENDPOINT-01`, remove only the CHG-020 harness and packages if they are no longer required:

```text
rm -rf /opt/mini-soc/yara
apt remove yara
apt autoremove
```

Before package removal, verify that no later change depends on YARA. Wazuh requires no rollback because CHG-020 did not modify its configuration.

## Residual risk

- Hash-only reputation can be incomplete or stale.
- A previously unseen hash can return no report.
- YARA signatures can produce false positives or false negatives depending on rule quality.
- VirusTotal availability and API limits remain external dependencies for enrichment only.
- This change is a controlled lab workflow, not production-grade malware analysis or automated threat-intelligence orchestration.

## Portfolio evidence

CHG-020 demonstrates local signature-based detection, deterministic testing, cryptographic hashing, data minimization, third-party trust-boundary awareness, secret handling, graceful degradation, analyst interpretation and reversible change governance.
