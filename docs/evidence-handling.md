# Evidence handling

## Classification

Evidence generated by the lab is treated as **private by default** until reviewed.

Raw output can contain:

- usernames;
- hostnames;
- internal IP addresses;
- interface details;
- package and kernel versions;
- service names and ports;
- paths;
- security configuration;
- packet captures;
- API responses.

## Repository policy

The following must not be committed to the public repository:

- credentials or passwords;
- API keys or access tokens;
- private keys;
- `.env` files containing secrets;
- raw PCAP/PCAPNG captures;
- raw baseline dumps;
- unredacted logs containing unnecessary identifiers;
- private files submitted to malware-analysis services.

Local raw evidence belongs under a path ignored by Git, or outside the repository entirely.

## Public evidence standard

A public artifact should explain:

1. the use case;
2. the expected detection;
3. the test performed;
4. the relevant sanitized result;
5. the analyst decision;
6. the MITRE ATT&CK mapping when applicable;
7. limitations and residual risk.

Screenshots without context are not considered sufficient evidence.

## VirusTotal

The default enrichment pattern is a SHA-256 lookup. Uploading files is not part of the normal workflow. Synthetic test samples can be used only when a specific experiment requires them and no private information is included.
